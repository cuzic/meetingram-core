# 合成会議の正解を作る手順

本文を通読し、議論の対象を issue、答えとなる案を position、案や理由への賛否を argument、明示的に合意した内容を decision、実行を引き受けた作業を action として手作業で記録した。問いが持ち越された場合も issue は残し、保留自体で解決した扱いにはしない。

各ノードに、内容を最初に示す発話と、その内容を具体化・言い直し・再確認した発話の `row_id` を付けた。相づちだけの発話や、同じ意味を繰り返した発話から独立のノードは作らない。行の前後関係で意味がつながる場合は、複数行を根拠に含める。話者ラベルだけから人物や担当者の同一性を判断しない。

`responds_to` で案を問いに、`supports` と `objects_to` で理由を対象の案または理由に、`resolves` で決定を問いに、`assigns` で宿題を決定または問いにつなぐ。正解の ID は会議内で一意で、発話 ID とは独立している。

評価では種類の一致と根拠の重なりを使う。複数候補があるときは重なりが最大の組から対応付け、同数の場合は予測 ID と正解 ID の順に処理する。重複数は、候補に挙がったが対応しなかった予測ノードの個数とする。
