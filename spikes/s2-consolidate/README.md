# ADR 0001 S2 整理の計測

[Issue #18](https://github.com/cuzic/meetingram-core/issues/18) のマージしない spike。コアの合成会議 6 本と、架空の展示会の運営を話し合う 60 分・600 発話の `long` を使う。`long.gold.json` の `duplicate_issue_pairs` は、同じ問いを表す前半と後半の正解ノード ID の組。

長い会議の宿題は、記録係が今日の判断を進行表に転記すると引き受けた発話（行 ID 8、18、…、598）を根拠に 60 件付けた。各 action は直前の決定（行 ID 7、17、…、597）に `assigns` で結ぶ。次の行にある条件付きの確認の提案は、引き受けた作業や担当の依頼が発話にないため含めていない。

## fake で再現

```sh
cd spikes/s2-consolidate
cargo test --locked
cargo run --locked -- run --backend fake --out results/fake
# 長い会議の baseline が入力上限を超えるため、run は終了コード 1 を返す。
cargo run --locked -- report --out results/fake
```

fake は最初の根拠を含む窓で正解のノードを返し、両端がそろった時点でエッジを返す。整理には空の操作列を返す。コアのプロンプト生成・応答解析・検証・評価を通し、7 本を流し切り、短い 6 本で両方式、長い 1 本で 2 段整理を完了する。長い会議の baseline は 1 回の入力上限（24,000 文字）を超え、試行は中断として記録される。

## Claude が sandbox の外で実行

認証済みの `claude` が PATH にある環境で実行する。

```sh
cd spikes/s2-consolidate
./run-matrix.sh results/s2
```

スクリプトは 3 通りの呼び出し数の見積もりを最初に表示する。sonnet と haiku の各 7 本を 6 件／45 秒の窓で流し切り、両方式の整理を各 3 回実行する。続いて sonnet の短い 6 本を 12 件／90 秒の窓で流し切り、2 段整理を 1 回実行する。見積もりは発話窓と分割前の整理の回数を足した値。分割、プロンプトの上限で窓に入りきらなかった発話、再試行によって実際の回数は増える。`MAX_CALLS` で実行ごとの上限を変更できる（既定 700）。各実行の途中で上限や失敗に達した場合は、その時点までの結果を集計して次の実行へ進む。1 件でも実行または集計が失敗した場合は最後に非ゼロで終了する。

単独で実行する場合は新しい出力ディレクトリを指定する。

```sh
cargo run --locked -- estimate --backend claude-cli --model sonnet
cargo run --locked -- run --backend claude-cli --model sonnet --out results/sonnet
cargo run --locked -- report --out results/sonnet
```

## 出力と判定

- 各会議の `flush.json` を起点として読み戻し、毎回同じグラフから整理を始める。解析できた応答はコアで操作ごとに検証する。抽出で連続 3 回失敗した会議は整理を省く。整理で 1 回失敗した試行は打ち切り、流し切りのグラフへ戻す。
- `calls.jsonl` は呼び出しごとの経過時間、入出力の文字数、解析の可否、検証で落とした操作数、エラー種別を記録する。CLI の作業場所は OS の一時ディレクトリに作り、終了時に削除する。グラフ JSON には合成会議の発話とノードの本文が含まれる。
- `RESULTS.md` は議題数、正解の issue 数、細かな問いの数、再現率、適合率、エッジ F1、誤 merge 数、正解の重複組の統合数、整理時間、タイムアウト数、呼び出し数、段 1 で省いた issue 数、段 2 で省いたノード数を試行ごとに表示する。重複組は整理前の別々の予測 issue を根拠で正解に対応付け、整理後の統合先が一致した組を数える。コアの誤 merge 指標では、長い会議で重複として注釈した別 ID 間の統合も誤 merge に含まれる。
- タスク 4b は sonnet の既定窓で判定する。短い 6 本では、2 段整理後の議題数の中央値を正解の issue 数で割り、6 本の比率の平均が 1.5 以下かを見る。誤 merge の中央値を足した件数は 2 以下、再現率の中央値は各会議で baseline 以上を条件とする。長い会議は 3 回のうち 2 回以上で正解の組が 1 組以上統合されれば条件を満たす。短い 6 本の両方式または長い会議の 2 段整理に未完了の試行があれば判定を保留する。
