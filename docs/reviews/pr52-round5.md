## Findings

### M1（Major）: 「実は両立できるかもしれない」という dd は、dd の矢印の理由ではなく、その反対を書かせる

- 根拠:
  - `cloud-system.txt:23` は「理由が見つからないときは、『実は両立できるかもしれない』という inferred の信念を書き、その打ち手に両立させる具体的なやり方を書く」とする。
    dd は同じ段の `:21` で「d と d2 が両立しないと考える理由」と定義されている。ADR 0006 §5 でも、前提は矢印の裏の「…だから」の理由として書く。
    「両立できるかもしれない」は矢印を否定する文で、前提にならない。図では「d と d2 は両立しない」の矢印の前提として
    「〔推測〕実は両立できるかもしれない…」と出るので、読む人には矛盾して見える。
  - この場合の良い例（`:34-35`）は「どちらの案も味が落ち着くまで置く手順が要り、同じ鍋は続けて使えないと考えられる」で、両立しない理由を書いている。
    規則と例が食い違っている。
  - r7 の dd 66 件のうち 13 件が「両立できるかもしれない」を含む。多くは「実は両立できるかもしれないが、〈理由〉」と、前置きの後に本来の理由が続く形。
    理由を持たず、矢印の反対だけを書いたものが 3 件ある。
    - 「…警告の出し先を役割で分ければ実は両立できるかもしれないから」（e2e-design/i-notice run3）
    - 「…実は端末を置いて歩くことと両立できるかもしれないから」（one-on-one/i-break run1）
    - 「約40サービス全体に同じ切り替え方式を使う必要があると考えられる（実はサービス群ごとに分ければ両立できるかもしれない）から」（m3/g2 run1。括弧の中が矛盾する）
- 修正案: `:23` の 2 文目を「理由が見つからないときも、最もありそうな理由を inferred の信念として書き、その打ち手に両立させる具体的なやり方を書く（『両立できるかもしれない』とは書かない）」にする。
  良い例の括弧書きは「理由が見つからない場合」にそろえる。直した後は、r8 で「両立できるかもしれない」を含む dd が 0 件になることだけを数えればよい。
